# 시크릿콜(SecretCall) — 종단간 암호화 음성통화 앱

개인정보 없이 **아이디만으로** 가입하고, 상대 아이디만 알면 **종단간 암호화(E2EE) 음성통화**를 할 수 있는 메신저(통화 전용).

## 목표 / 비목표

- ✅ 1:1 음성통화 (E2EE)
- ✅ 개인정보 미수집: 개발사가 발급한 `아이디 + 1회용 등록코드`로 가입
- ✅ 상대 아이디만 알면 통화 가능
- ✅ 배포형(안드로이드/iOS)
- ❌ 문자/채팅 없음
- ❌ 연락처/전화번호/이메일 등 개인정보 수집 없음

## 전체 구조

```
[모바일 앱 A] ──WebSocket(시그널링)──┐
                                     ├── [시그널링 서버]  (신호만 중개, 음성 안 지남)
[모바일 앱 B] ──WebSocket(시그널링)──┘         │
     │                                        └── [JSON 파일] 아이디·공개키만 저장
     │
     └───────── WebRTC P2P (DTLS-SRTP, E2EE 음성) ─────────┐
                                                            │
                                        [STUN/TURN(coturn)] └ P2P 실패 시에만 암호화된 채로 중계
```

## 종단간 암호화(E2EE) 설계

1. **미디어 암호화 (기본 제공):** WebRTC 음성은 DTLS-SRTP로 암호화되며, 키는 두 기기가 직접 교환한다. 서버는 미디어 키를 모른다.
2. **중간자 공격(MITM) 방지:** 시그널링 서버가 SDP를 중계하므로, 악의적 서버가 DTLS 지문을 바꿔치기하는 공격이 이론상 가능하다. 이를 막기 위해:
   - 각 사용자는 **Ed25519 신원 키쌍**을 기기에서 생성한다. 개인키는 절대 기기를 벗어나지 않는다.
   - 통화 SDP의 DTLS 지문에 신원 개인키로 **서명**하여 상대에게 보낸다.
   - 상대는 서버에서 받은(또는 이전에 고정해 둔) 신원 공개키로 서명을 검증한다.
   - **안전번호(Safety Number)** = 두 사람의 신원 공개키를 합쳐 만든 지문. 두 화면에 같은 번호가 뜨면 도청 없음이 보장된다(최초 1회 육안/구두 확인, TOFU).

## 가입/인증 플로우 (개인정보 없음)

```
[관리자]  아이디 발급  →  user_id + registration_code(1회용) 생성
   │
   └─(오프라인 전달: 문자/구두 등 개발사 재량)→ [사용자]

[사용자 앱]
  1. user_id + registration_code 입력
  2. 앱이 신원 키쌍(Ed25519) 생성 → 개인키는 기기 보안저장소에 보관
  3. 서버로 { user_id, registration_code, identity_public_key } 전송
  4. 서버: 코드 일치·미사용 확인 → 공개키 저장, 코드 소각, auth_token 발급
  5. 이후 접속은 user_id + auth_token 으로 인증
```

- 저장되는 데이터: `user_id`, `identity_public_key`, `auth_token 해시`, 가입시각. **끝.**
- 전화번호·이메일·이름·연락처 없음.
